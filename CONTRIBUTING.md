# Contributing Guidelines

These rules help us keep the project organised and make teamwork easier.

## 1. Create an issue first

Before starting any work, create an issue that describes the task.

## 2. Create a new branch

Do not work directly on the `main` branch. Create a separate branch for each task.

The branch name should start with one of the following prefixes:

- `feature/` — for a new feature, for example `feature/login-page`,
- `docs/` — for documentation changes, for example `docs/update-readme`,
- `refactor/` — for improving the code structure without changing its behaviour`.

## 3. Make and test your changes

Before submitting your changes:

- make sure the code compiles,
- run all available tests,
- check that the changes complete the task described in the issue.

## 4. Create a pull request

Changes can be added to the `main` branch only through a pull request (PR). Direct pushes to `main` are not allowed.

In the pull request:

- briefly describe your changes,
- explain how they were tested,
- link the related issue, for example `Closes #12`.

The PR should be reviewed and approved before it is merged into the `main` branch.
